# TradingView Indicator Scraper

A Python script using raw Chrome DevTools Protocol (CDP) over WebSockets to connect to your active Chrome browser session and scrape indicator values in real-time from an active TradingView chart.

## Prerequisites

1. **Python**: Ensure you have Python installed. You can check by running `python --version` in your terminal.
2. **Google Chrome**: Ensure Google Chrome is installed.

## Setup Instructions

### 1. Launch Chrome in Remote Debugging Mode

For the Python script to connect to your active Chrome session, you must start Chrome with remote debugging enabled and allow connections from local origins. 

**Close all existing Chrome windows first** to ensure flags are registered properly.

#### On Windows (Local Machine):
Open a terminal or Command Prompt and run the following command:
```powershell
Start-Process -FilePath "C:\Program Files\Google\Chrome\Application\chrome.exe" -ArgumentList "--remote-debugging-port=9222", "--remote-allow-origins=*", "--user-data-dir=C:\src\antigravity\IndexTimeMachine\ChromeProfile", "--no-first-run", "--no-default-browser-check", "--disable-search-engine-choice-screen", "--disable-sync"
```

#### On Linux VPS (Headless):
1. Install virtual framebuffer and browser packages:
   ```bash
   sudo apt update
   sudo apt install -y xvfb libxi6
   wget https://dl.google.com/linux/direct/google-chrome-stable_current_amd64.deb
   sudo apt install ./google-chrome-stable_current_amd64.deb
   rm google-chrome-stable_current_amd64.deb
   ```
2. Start Chrome running under `Xvfb` in the background, preloading TradingView:
   ```bash
   xvfb-run --server-args="-screen 0 1920x1080x24" google-chrome --remote-debugging-port=9222 --user-data-dir="./ChromeProfile" --remote-allow-origins="*" --no-sandbox "https://www.tradingview.com" &
   ```
3. Set up an SSH tunnel from your local PC to inspect the remote browser session:
   ```bash
   ssh -L 9223:localhost:9222 ujjwal@your-vps-ip
   ```
4. Open a local Chrome/Edge browser, navigate to `chrome://inspect`, click **Configure...**, add `localhost:9223`, and click **inspect** under your remote target to sign in to TradingView and select your chart.

The script will:

## Troubleshooting

- **"Chrome debugging port 9222 is not reachable"**: Verify that you closed all other Chrome processes before launching Chrome with the debugging parameters, and that it is running successfully.
- **"Connection to WebSocket failed"**: Ensure you included the `"--remote-allow-origins=*"` flag when launching Chrome. Without this flag, Chrome blocks WebSocket connections from external processes.
- **"TradingView tab not found"**: Make sure you have a tab open with `tradingview.com` in its URL.

# Trade Executor

The Trade Executor coordinates the visual strategy signals generated by the scraper with the Dhan API, managing risk controls, position sizing, and trade executions.

## Core Strategy Logic

1. **Time Candle**: The 5-minute candle at the morning or afternoon target times (e.g. 09:15 and 12:15).
2. **Trigger Candle**: The first 5-minute candle that closes *beyond* the High of the Time Candle (for CE / Buy) or below the Low of the Time Candle (for PE / Sell).
3. **Position Candle (Entry)**: Triggered immediately when the spot index price *breaks* (crosses in real-time) the High of the Trigger Candle (for CE) or the Low of the Trigger Candle (for PE).
4. **Dynamic Trade Levels**:
   * **Stop Loss**: Opposite side of the Time Candle range (e.g. Range Low for CE, Range High for PE), evaluated on a **5-minute candle close** basis to prevent noise shakes.
   * **Target**: Real-time index LTP crossing a **1:2 Risk-to-Reward ratio** from the entry breakout level (with steps $T1$ through $T5$).
5. **Aesthetics & Noise Mitigation (Time Machine strategy only)**:
   * **Spike Guard (2-tick Debounce)**: Real-time option P&L check requires **2 consecutive ticks** below the Max Capital Risk threshold before triggering emergency square-offs, avoiding phantom exits on brief spread spikes.
   * **Trailing SL Buffer**: Trailing SL updates (after T1-T4 hits) include a **50% of original risk buffer** (`original_risk * 0.5`) to allow index fluctuations without stopping out profitable positions early.
   * **Direction-Guarded Re-entries**: Allowed **once per cycle** after a stop-loss or max-loss exit, but strictly guarded to ensure the indicator signal direction (Operator) has not flipped since the original entry.
6. **Theta Protection (Expiry Skip)**:
   * Skips same-week (DTE 0) and < 3 calendar days away weekly contract expiries.
   * Automatically trades next week's weekly option contract.

## Background & Multi-Instance Execution

### 1. Unique Process Locking
The executor enforces a single-process rule per index using native filesystem locks (via `msvcrt` on Windows and `fcntl` on Unix/Linux). 
* Attempting to start a duplicate process for an already running index (e.g. starting a second `"Nifty 50"` script) will immediately print an error and exit to prevent rate limit and trade conflicts:
  ```text
  [ERROR] Another instance is already running for Nifty 50. Exiting to prevent conflict.
  ```

### 2. Self-Healing Authentication
Dhan invalidates all previous access tokens when a new one is generated. To support multiple concurrent indexes without authentication clashes:
* When an active token is invalidated, the script detects it, cleans the cache, and triggers a dynamic TOTP login.
* Before generating a new token, the script checks if another index process has already generated a fresh token in the shared `.dhan_token.json` cache, automatically reusing it without triggering rate limits.

## Monitoring and Diagnostics

### 1. Check Running Instances
To see how many trade executor scripts are active:

#### In Windows (PowerShell):
```powershell
Get-CimInstance Win32_Process -Filter "name = 'python.exe' and CommandLine like '%trade_executor.py%'" | Select-Object ProcessId, ParentProcessId, CommandLine | Format-Table -Wrap
```
*Note: Due to Windows virtual environment architecture, you will see two process IDs per active index (one parent wrapper process and one child interpreter process). This corresponds to exactly one logical instance.*

#### On Linux VPS:
```bash
ps aux | grep trade_executor.py
```

### 2. View Logs in Real-Time (equivalent to `tail -f`)
To monitor execution logs dynamically as trades occur:

#### In Windows (PowerShell):

```powershell
Get-Content .\logs\log_Nifty_50.txt -Wait -Tail 20
```

#### On Linux VPS:
```bash
tail -f logs/log_Nifty_50.txt
```

### 3. Terminate / Kill Running Processes
If background scripts or Chrome instances are left unclosed, use these commands to terminate them:

#### On Windows (PowerShell):
* **Kill trade executors**:
  ```powershell
  Get-CimInstance Win32_Process -Filter "name = 'python.exe' and CommandLine like '%trade_executor.py%'" | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
  ```
* **Kill Chrome remote debugging instances**:
  ```powershell
  Stop-Process -Name "chrome" -Force
  ```

#### On Linux VPS (Bash):
* **Kill trade executors**:
  ```bash
  pkill -f trade_executor.py
  ```
* **Kill Chrome and virtual display (Xvfb)**:
  ```bash
  pkill -f chrome
  pkill -f Xvfb
  ```
* **Free up the debugging port (9222 / 9223)**:
  ```bash
  fuser -k 9222/tcp 2>/dev/null
  fuser -k 9223/tcp 2>/dev/null
  ```

# Offline Backtester

The offline backtest utility allows simulating historical strategy runs for any specific calendar date using historical 1-minute index candles and option close prices loaded dynamically from Dhan.

## Instructions
1. Open [data/scrap_Nifty_50.json](file:///c:/src/antigravity/IndexTimeMachine/data/scrap_Nifty_50.json) and add/repopulate the indicator parameters for the target date. Ensure the `"Timestamp"` field begins with the target date formatted as `YYYY-MM-DD` (e.g. `"2026-08-04 11:23:48"`).
2. Run the backtester via Python, passing the target date as the argument:
   ```powershell
   .\venv_314\Scripts\python.exe scratch\backtest_today.py YYYY-MM-DD
   ```
3. The script will dynamically download historical index candles, resolve the F&O contract expiry for that date, download corresponding historical options candles, and simulate the execution loop (including budget risk sizing and 5-level trailing Stop Losses) in 1-minute intervals.

# Performance Report Generator

The performance report generator aggregates executed trades from all daily index logs (located in the `logs/` directory), dynamically queries Dhan for missing option premiums, and builds a premium interactive HTML dashboard.

## Instructions
1. Run the report generator script:
   ```powershell
   .\venv_314\Scripts\python.exe reports/generate_report.py
   ```
2. The script will:
   * Execute `reports/extract_trades.py` to scan new logs and update the central ledger `reports/trade_ledger.json`.
   * Parse target ranges, exits, entries, and index levels.
   * Query the Dhan API to fetch option exit premiums (if not cached).
   * Save the parsed data to the central database `reports/trade_ledger.json` to prevent API rate limits.
   * Generate `reports/index.html`.
   * *Note: You can skip log extraction and only compile using the `--skip-extract` flag.*
3. Open [reports/index.html](file:///c:/src/antigravity/IndexTimeMachine/reports/index.html) in any web browser to view:
   * **Key KPIs**: Net PnL (INR), total trades, win rate %, and profit factor.
   * **PnL Charts**: Visual asset-wise bar chart.
   * **Filterable Trade Ledger**: Filter trades by index.
   * **Slide-out Log Drawer**: Click on any trade row to view full details along with the exact raw logs captured during that execution cycle.
